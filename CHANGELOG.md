v0.1.0
=========================
Estate Atlas (повна переробка бота під новий домен - каталог нерухомості)
* перехід з MySQL/service-account-набору файлів на єдину інтеграцію з Google
  Sheets + Google Drive через OAuth "Desktop app" (gspread.oauth), без
  сервісного акаунта
* нова функція "➕ Додати об'єкт" - 12-кроковий майстер на FSM (aiogram
  StatesGroup) з кнопками Назад/Далі/Головне меню на кожному кроці,
  завантаженням фото/відео на Google Drive і записом у відповідний аркуш
  (= населений пункт) Google Таблиці; "Площа, м²" і "Площа ділянки, сот."
  - два окремі незалежні кроки (запитуються завжди, незалежно від
  обраного типу об'єкта)
* нова функція "🔎 Пошук" - вибір населеного пункту зі списку аркушів,
  видача об'єктів партіями з кнопкою "Показати ще", кнопки-посилання на
  фото/відео в Drive, кнопка "✏️ Редагувати"
* редагування об'єкта веде в той самий майстер з кроку "Ціна" зі
  збереженням поточних значень полів
* опційний контроль доступу (ADMINS) для додавання/редагування
* збережено підхід до логування й обробки помилок (logging + try/except)
  та оновлення для надійності звернень до Google API (tenacity)
* видалено застарілі файли попередньої (MySQL / payment-checking) версії
  бота: db.py, models.sql, README_SQL.md, gspread_create.py,
  handlers/cities.py, старий gspread_client.py
* фікс: реальна таблиця Google Sheets спочатку була завантаженим
  `.xlsx`-файлом (Sheets API з такими не працює) - сконвертовано в рідний
  формат Google Таблиць, ID у `.env` оновлено
* фікс: назва колонки площі ділянки виправлена на реальну з таблиці -
  "Площа ділянки, сот." (з комою) замість "Площа ділянки сот."
* нова змінна `EXCLUDED_SHEETS` - виключає з вибору "населений пункт"
  технічні аркуші таблиці (довідники, зведені каталоги), які не є
  населеними пунктами
* фікс: завантаження декількох фото/відео "стеком" одночасно спричиняло
  TimeoutError і втрату частини файлів (race condition - паралельні
  обробники читали застарілий стан FSM) - серіалізовано на користувача
* "🔎 Пошук" тепер показує фото як справжні зображення/альбом-колаж
  (а не лише кнопками-посиланнями) - відео залишені посиланнями, щоб не
  навантажувати пам'ять бота
* нова змінна `GOOGLE_OAUTH_FLOW` (`local_server`/`console`) - підтримка
  першого входу Google-акаунтом на headless-сервері без браузера
* README: інструкція встановлення Python (Windows/Ubuntu Server), venv,
  headless-OAuth для сервера, приклад systemd-сервісу для постійної роботи
* фікс: `requirements.txt` вимагав `aiogram>=3.31`, а жодна версія aiogram
  від 3.23 до 3.31 ще не підтримує щойно випущений Python 3.15
  (`Requires-Python <3.15`) - встановлення падало з "No matching
  distribution found" на машинах зі свіжовстановленим Python 3.15+;
  нижню межу знижено до `>=3.3`, щоб pip сам підбирав сумісну версію під
  будь-який Python 3.10+; README тепер явно радить ставити 3.13/3.14,
  а не "найновішу" версію з головної сторінки python.org
* README: додано примітку - помилка "Building wheel for aiohttp /
  pydantic-core ... error" при `pip install` означає ту саму причину
  (немає готової бінарної збірки під надто нову версію Python, pip
  намагається компілювати з коду) - рішення: Python 3.13/3.14, а не
  встановлення компілятора
* README: рекомендована версія Python зафіксована на конкретній -
  спочатку було **3.11.5**, уточнено до **3.14.8** (останній патч
  останньої гілки, яку ще підтримує `aiogram`, межа `<3.15`; на момент
  написання має повне покриття бінарними wheel-збірками важких
  залежностей, на відміну від щойно випущеної 3.15) - для Windows готова
  PowerShell-команда тихого встановлення саме цієї версії поруч з уже
  наявними (не чіпаючи їх), і скрізь `py -3.14` / `python3.14` замість
  неоднозначного `python`, щоб гарантовано створювався venv на потрібній
  версії навіть на машині з кількома Python одночасно
* фікс: `ImportError: cannot import name 'console_flow' from 'gspread.auth'`
  на свіжому `pip install` - бібліотека `gspread` прибрала з коду мертвий
  "console"-флоу входу (Google відключив цей протокол ще в лютому 2022,
  а не лише щойно); прибрано змінну `GOOGLE_OAUTH_FLOW` і весь пов'язаний
  код/документацію - авторизація завжди йде через `local_server_flow`;
  README: інструкція для headless-сервера без браузера замінена на
  робочий спосіб через SSH port-forward (`ssh -L 8080:localhost:8080`)
* нова колонка таблиці "Відео TikTok" - новий (13-й) крок майстра "Додати
  об'єкт" одразу після "Посилання" (посилання на відео, необов'язково);
  "🔎 Пошук" показує рядок з лінком на TikTok у картці об'єкта, лише якщо
  комірка не порожня
* нова змінна `.env` `MEDIA_STORAGE` (`telegram` / `googledrive`) -
  перемикає, куди зберігаються фото/відео з майстра "Додати об'єкт":
  - `telegram` (нове значення за замовчуванням) - без жодних завантажень,
    зберігається лише Telegram `file_id` з повідомлення користувача; немає
    обмеження на обсяг даних і на розмір файлу (не діє ліміт ~20 МБ на
    завантаження Bot API); "🔎 Пошук" надсилає фото/відео напряму
    (`answer_photo`/`answer_video` з file_id) - без жодного мережевого
    звернення до Google Drive
  - `googledrive` - попередня поведінка (файл довантажується з Telegram і
    перезавантажується на Drive, у таблицю йде лінк) лишена без змін і
    повністю працездатна
  - перемикається в будь-який момент; формат уже збереженого значення
    визначається автоматично за виглядом рядка (а не за поточним
    налаштуванням), тож старі об'єкти в іншому форматі й надалі коректно
    показуються в пошуку
* "🔎 Пошук" тепер показує й відео напряму в чаті (`answer_video`), якщо
  воно збережене як Telegram `file_id` - кнопка-посилання лишається лише
  для відео, завантажених на Google Drive
