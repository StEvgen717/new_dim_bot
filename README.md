# 🏘️ Estate Atlas — Telegram-бот каталогу нерухомості

Telegram-бот для ведення каталогу об'єктів нерухомості в Google Таблиці:
додавання оголошень (із фото/відео - за замовчуванням зберігаються просто
як Telegram-файли, опційно - на Google Drive, перемикається налаштуванням
`MEDIA_STORAGE`) та пошук об'єктів за населеним пунктом.

Кожен аркуш Google Таблиці відповідає одному населеному пункту й містить
список об'єктів нерухомості в ньому.

---

## 🔧 Налаштування Google Cloud (один раз)

1. Створіть проєкт у [Google Cloud Console](https://console.cloud.google.com/).
2. У **APIs & Services → Library** увімкніть **Google Sheets API** (обов'язково
   для будь-якого режиму).
3. Створіть Google Таблицю (кожен аркуш - населений пункт, див. структуру
   нижче) і скопіюйте її ID у `.env` (`GOOGLE_SPREADSHEET_ID` - частина URL
   після `/d/`).

Далі залежить від `MEDIA_STORAGE` у `.env`:

| `MEDIA_STORAGE` | Доступ до Google Таблиці | Фото/відео в майстрі |
|---|---|---|
| **`telegram`** (рекомендовано) | **Сервісний акаунт** - без `token.json`, без 7-денного OAuth | Telegram `file_id` у комірках |
| **`googledrive`** | OAuth `token.json` + `google-oauth-client.json` | Завантаження на Google Drive |

Нижче - покрокові інструкції для обох варіантів.

### Сервісний акаунт для `MEDIA_STORAGE=telegram`

Підходить для сервера/Jenkins: бот працює **місяцями без браузера** і без
оновлення `token.json`.

1. У тому ж проєкті Google Cloud увімкніть **Google Drive API** (не для
   завантаження нових файлів, а лише щоб у пошуку можна було показати **старі**
   фото з лінками `drive.google.com`, якщо такі рядки ще є в таблиці).
2. **IAM & Admin → Service Accounts** → **+ CREATE SERVICE ACCOUNT**.
   - Service account name: напр. `estate-atlas-bot`;
   - натисніть **Create and Continue** → **Done** (ролі на рівні проєкту
     для Sheets **не обов'язкові** - доступ дамо через «Поділитися» таблицею).
3. Відкрийте створений акаунт → вкладка **Keys** → **Add key** → **Create new
   key** → тип **JSON** → завантажиться файл.
4. Перейменуйте його на `google-service-account.json` і покладіть у `bot/`
   (поруч із `main.py`). У `.env` вкажіть:
   `GOOGLE_SERVICE_ACCOUNT_FILE=google-service-account.json`.
5. Відкрийте завантажений JSON у текстовому редакторі і знайдіть поле
   **`client_email`** - виглядає як `something@your-project.iam.gserviceaccount.com`.
6. Відкрийте вашу **Google Таблицю** (у браузері, під своїм акаунтом) →
   кнопка **Надати доступ** / **Share** → вставте цей `client_email` → роль
   **Редактор** (Editor) → надіслати / зберегти.
7. У `.env` поставте `MEDIA_STORAGE=telegram`. Файли `token.json` і
   `google-oauth-client.json` для цього режиму **не потрібні** (можна не
   класти на сервер).

Перевірка: з папки `bot/` запустіть `python main.py` - у логах має бути
рядок на кшталт «сервісний акаунт, таблиця '…'». Якщо помилка доступу -
перевірте крок 6 (email саме з JSON, права Редактор).

### OAuth для `MEDIA_STORAGE=googledrive`

1. Увімкніть **Google Drive API** (якщо ще не увімкнено).
2. **APIs & Services → OAuth consent screen**: User type **External**, додайте
   свій Google-акаунт у **Test users**.
3. **Credentials → + CREATE CREDENTIALS → OAuth client ID** → **Desktop app**
   → завантажте JSON → `bot/google-oauth-client.json`.
4. Створіть папку на Drive для фото/відео, її ID - у `GOOGLE_DRIVE_FOLDER_ID`.
5. У `.env`: `MEDIA_STORAGE=googledrive`. Перший запуск - розділ **«Перший
   запуск»** нижче (`token.json`).

## ⚙️ Файл `.env`

Скопіюйте `bot/.env.example` у `bot/.env` і заповніть:

| Змінна | Опис |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота від [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_BOT_USERNAME` | юзернейм бота (інформативно) |
| `GOOGLE_PROJECT_ID` | ID проєкту в Google Cloud |
| `GOOGLE_SPREADSHEET_ID` | ID Google Таблиці (з її URL) |
| `GOOGLE_SHEET_NAME` | назва таблиці (для перевірки/логів) |
| `MEDIA_STORAGE` | `telegram` (за замовчуванням) або `googledrive` - також вибирає **тип входу в Google** (див. таблицю вище) |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | шлях до JSON-ключа SA (лише для `MEDIA_STORAGE=telegram`, за замовч. `google-service-account.json`) |
| `GOOGLE_DRIVE_FOLDER_ID` | ID папки на Drive (лише для `MEDIA_STORAGE=googledrive`) |
| `GOOGLE_OAUTH_CLIENT_FILE` | шлях до `google-oauth-client.json` (лише для `googledrive`) |
| `GOOGLE_OAUTH_TOKEN_FILE` | шлях до `token.json` (лише для `googledrive`, створюється при першому вході) |
| `ADMINS` | Telegram ID через кому, яким дозволено "Додати об'єкт"/"Редагувати". Порожньо = дозволено всім |
| `SEARCH_PAGE_SIZE` | скільки об'єктів показувати за раз у пошуку (за замовчуванням 5) |
| `EXCLUDED_SHEETS` | назви аркушів через кому, які існують у таблиці, але НЕ є населеними пунктами (довідники, зведені каталоги тощо) - не показуються в боті |

⚠️ **Ніколи не комітьте** `.env`, `google-service-account.json`,
`google-oauth-client.json` і `token.json` - вони в `.gitignore`.

## 🐍 Встановлення Python (якщо ще не встановлено)

Потрібна конкретно **Python 3.14.8** (останній патч останньої версії,
яку ще підтримує `aiogram` - межа `<3.15`; і бот, і всі залежності вже
мають готові бінарні збірки саме під неї, без компіляції).

> ⚠️ **Не беріть версію "наосліп" з головної кнопки завантаження.** Великі
> бібліотеки (напр. `aiogram`, `aiohttp`, `pydantic-core`) після виходу
> нової мажорної версії Python (напр. 3.15) якийсь час її ще не
> підтримують: `pip install -r requirements.txt` або падає з
> `Requires-Python` / `No matching distribution found`, або (гірше)
> намагається **компілювати** залежності з коду і падає на кроці
> "Building wheel for aiohttp" / "Building wheel for pydantic-core" (бо
> немає Rust/C++ компілятора). Якщо вже стоїть новіша версія - не
> видаляйте її, просто встановіть 3.14.8 поруч (команда нижче) і
> створюйте venv саме через `py -3.14`.

### Windows

**Швидкий спосіб (PowerShell, ставить саме 3.14.8, не чіпаючи інші
версії Python, якщо вони вже є):**
```powershell
$installer = "$env:TEMP\python-3.14.8-amd64.exe"
Invoke-WebRequest "https://www.python.org/ftp/python/3.14.8/python-3.14.8-amd64.exe" -OutFile $installer
Start-Process $installer -ArgumentList "/quiet InstallAllUsers=0 PrependPath=1 Include_launcher=1" -Wait
Remove-Item $installer
py -3.14 --version
```
Останній рядок має показати `Python 3.14.8`.

**Або вручну:** завантажте інсталятор "Windows installer (64-bit)" зі
сторінки [python.org/downloads/release/python-3148](https://www.python.org/downloads/release/python-3148/)
і на першому екрані інсталятора поставте галочку **"Add python.exe to
PATH"** - без цього команда `python` не працюватиме в терміналі (`pip`
ставиться разом з Python автоматично).

Далі, незалежно від способу встановлення:

1. Перевірте в PowerShell:
   ```powershell
   py -3.14 --version
   py -3.14 -m pip --version
   ```
2. (Рекомендовано) Створіть віртуальне середовище прямо в папці проєкту -
   щоб залежності бота не змішувались з іншими Python-проєктами, і щоб
   напевно використовувалась саме 3.14.8, навіть якщо на машині є й інші
   версії Python:
   ```powershell
   cd D:\Bots\TelegramBot
   py -3.14 -m venv .venv
   .venv\Scripts\Activate.ps1
   python --version
   ```
   Останній рядок (вже всередині активованого venv) теж має показати
   `Python 3.14.8`.
   Якщо PowerShell відмовляється запускати скрипт активації
   (`...running scripts is disabled on this system`), виконайте одноразово:
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```
   і підтвердьте (`Y`), потім повторіть активацію. Після активації перед
   рядком у терміналі з'явиться `(.venv)`.

### Ubuntu Server

1. Оновіть списки пакетів і встановіть Python, pip та venv (на Ubuntu
   `venv` - окремий пакет, його треба ставити явно):
   ```bash
   sudo apt update
   sudo apt install -y python3 python3-pip python3-venv git
   ```
2. Перевірте версію: `python3 --version`. Якщо показує щось у діапазоні
   3.11-3.12 - цього достатньо, можна пропустити решту цього пункту.
   Якщо потрібна саме **3.14** (а в стандартному репозиторії її немає),
   додайте PPA `deadsnakes` і ставте явно `python3.14` (**не**
   "найновішу" 3.15 - див. застереження вище):
   ```bash
   sudo add-apt-repository ppa:deadsnakes/ppa
   sudo apt update
   sudo apt install -y python3.14 python3.14-venv
   ```
3. Перенесіть проєкт на сервер (`git clone` вашого репозиторію, або
   `scp -r` з локальної машини) і створіть віртуальне середовище - якщо
   ставили `python3.14` окремо кроком 2, викликайте саме його:
   ```bash
   cd TelegramBot
   python3.14 -m venv .venv
   source .venv/bin/activate
   python --version
   ```
   Після активації перед рядком з'явиться `(.venv)`. Деактивувати - команда
   `deactivate`.

> У всіх прикладах нижче (`pip install`, `python main.py`) мається на увазі,
> що віртуальне середовище вже активоване в поточному терміналі.

## 🚀 Запуск

```bash
pip install -r requirements.txt
cd bot
python main.py
```

(на Ubuntu команди ті самі - venv вже підміняє `python`/`pip` на `python3`/`pip3` з `.venv`)

### Перший запуск (одноразово) - вхід Google-акаунтом

> Потрібно **лише** якщо `MEDIA_STORAGE=googledrive`. Для `telegram` див.
> розділ «Сервісний акаунт» вище - браузер не потрібен.

Авторизація - через OAuth "Desktop app" (`gspread.auth.local_server_flow`):
при запуску `python main.py` бот сам відкриває браузер на цій же машині із
запитом увійти Google-акаунтом, що має доступ до таблиці й папки на Drive.
Після підтвердження поруч з `main.py` з'явиться файл `token.json` - далі
бот працюватиме автоматично, без повторного входу (токен оновлюється сам).

> Альтернативний "console"-флоу (вхід без браузера взагалі, через код,
> вставлений у термінал) **не підтримується** - Google відключив цей
> протокол ще в лютому 2022, а бібліотека `gspread` прибрала його з коду.

**Ubuntu Server (headless, без браузера)** - два робочі варіанти:

1. *Найпростіше* - пройдіть цей самий перший вхід один раз на машині з
   браузером (наприклад, на своєму Windows ПК за інструкцією вище - у вас
   він уже пройдений), а потім скопіюйте на сервер **обидва** файли:
   `bot/google-oauth-client.json` і `bot/token.json` (напр. через `scp`).
   Сервер далі лише оновлюватиме токен автоматично по HTTP, браузер йому
   взагалі не знадобиться.
2. *Або* - пройдіть вхід прямо на сервері, перенаправивши браузер зі своєї
   машини через SSH (`local_server_flow` слухає порт на сервері - просто
   тунелюємо його до себе):
   ```bash
   # на своїй машині (не на сервері) - підмініть user@server:
   ssh -L 8080:localhost:8080 user@server
   ```
   У цій же SSH-сесії запустіть `python main.py` на сервері - він
   надрукує посилання авторизації (на порту 8080) і буде його чекати.
   Відкрийте надруковане посилання у браузері **на своїй машині** - запит
   піде через тунель прямо на сервер, і там з'явиться `token.json`.

Якщо потрібно увійти іншим акаунтом або змінити права доступу - видаліть
`token.json` і запустіть бота знову (повторно пройде той самий сценарій).

> ⚠️ Це стосується **лише** `MEDIA_STORAGE=googledrive`: у режимі Testing
> OAuth діє ~7 днів, потім `token.json` треба оновлювати (видалити файл і
> знову пройти вхід). На сервері без браузера зручніше **`MEDIA_STORAGE=telegram`**
> і сервісний акаунт - без цього ліміту.

### Постійна робота на Ubuntu Server (systemd)

Якщо просто закрити SSH-сесію, `python main.py` зупиниться разом з нею.
Щоб бот працював постійно й сам піднімався після перезавантаження сервера,
створіть systemd-сервіс:

```bash
sudo nano /etc/systemd/system/estate-atlas-bot.service
```

```ini
[Unit]
Description=Estate Atlas Telegram Bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/TelegramBot/bot
ExecStart=/home/ubuntu/TelegramBot/.venv/bin/python main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

(змініть `User` і шляхи `WorkingDirectory`/`ExecStart` на свої) і запустіть:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now estate-atlas-bot
sudo systemctl status estate-atlas-bot   # перевірити стан
journalctl -u estate-atlas-bot -f        # дивитись логи наживо
```

## 📦 Функціонал

### ➕ Додати об'єкт

Майстер із 13 кроків, кожен із кнопками **🔙 Назад** / **📝 Головне меню**
(а для кроків, де нічого вводити не обов'язково, - ще й **➡️ Далі**):

1. **Населений пункт** - обов'язково, зі списку аркушів таблиці
2. **Тип угоди** - обов'язково: Продаж / Оренда
3. **Тип об'єкта** - обов'язково: Будинок / Квартира / Ділянка / Комерція
4. **Ціна** - необов'язково
5. **Валюта** - USD / грн, необов'язково
6. **Площа, м²** - окремий крок, необов'язково (запитується завжди, незалежно від типу об'єкта)
7. **Площа ділянки, сот.** - окремий крок, необов'язково (запитується завжди, незалежно від типу об'єкта)
8. **Опис** - необов'язково
9. **Фото** - можна декілька; куди саме зберігаються - залежить від `MEDIA_STORAGE` (див. нижче)
10. **Відео** - можна декілька; куди саме зберігаються - залежить від `MEDIA_STORAGE` (див. нижче)
11. **Адреса / локація** - текст, геолокація або посилання Google Maps
12. **Посилання** на оголошення - необов'язково
13. **Відео TikTok** - посилання, необов'язково; після цього кроку об'єкт зберігається в таблицю

Новий рядок одразу отримує статус «Активний».

#### Де зберігаються фото/відео (`MEDIA_STORAGE`)

Одне й те саме налаштування визначає і **медіа**, і **вхід у Google**:
`telegram` → сервісний акаунт для таблиці; `googledrive` → OAuth
`token.json` (див. таблицю на початку README).

Воно перемикає, куди йдуть фото/відео з кроків 9-10 (TikTok - завжди
текстове посилання):

- **`telegram`** (за замовчуванням) - нічого нікуди не завантажується,
  зберігається лише Telegram `file_id` (ідентифікатор, який бот отримує
  одразу з повідомлення). Немає лімітів за обсягом, не навантажує диск чи
  Google API - але сама комірка "Фото"/"Відео" в таблиці стає нечитабельною
  для людини (довгий беззмістовний рядок, не клікабельний) і Telegram
  офіційно не гарантує довічне зберігання медіа бота.
- **`googledrive`** - як було в першій версії: файл довантажується з
  Telegram і перезавантажується на Google Drive, у таблицю йде клікабельний
  лінк. Вимагає Google Drive API (див. "Налаштування Google Cloud" вище) і
  витрачає квоту Google Drive акаунта.

Перемикати можна в будь-який момент - бот визначає формат уже збереженого
значення автоматично (за виглядом рядка), тож старі об'єкти в іншому
форматі й надалі показуються коректно, незалежно від поточного налаштування.

### 🔎 Пошук

Користувач обирає населений пункт (= аркуш таблиці) зі списку, бот показує
всі об'єкти цього аркуша, де заповнена колонка «Тип угоди» (партіями по
`SEARCH_PAGE_SIZE`, з кнопкою **"➡️ Показати ще"**). Для кожного об'єкта:

1. спочатку - **фото як справжні зображення**: одне фото окремим
   повідомленням або **альбом-"колаж"**, якщо декілька (стандартна
   поведінка Telegram). Telegram `file_id` передається напряму (без
   завантаження); лінк на Google Drive - довантажується байтами бота.
   Формат визначається автоматично за виглядом значення, незалежно від
   поточного `MEDIA_STORAGE`. Якщо фото не вдалось показати (Drive
   недоступний) - воно не зникає, а стає кнопкою-посиланням у картці
   нижче (можливо лише для Drive-лінків - `file_id` кнопкою не показати);
2. потім - **відео**: `file_id` надсилається напряму (`answer_video`,
   без завантаження, нуль пам'яті бота); відео, збережене лінком на
   Google Drive, лишається inline-кнопкою-посиланням (завантаження у
   браузері користувача - відеофайли важчі, тримати їх у пам'яті бота
   немає сенсу);
3. потім - текстова картка: тип угоди/об'єкта, ціна, площа, адреса/локація,
   опис, посилання на оголошення й на відео TikTok (лише якщо заповнено);
4. inline-кнопки під карткою: фолбек-посилання на ті фото/відео з Google
   Drive, які не вдалось показати напряму вище (для `file_id` фолбек-кнопки
   не буває - там або показалось, або пропущено з логом);
- кнопку **✏️ Редагувати**, яка одразу відкриває майстер додавання об'єкта
  з кроку 4 ("Ціна") із підставленими поточними значеннями - населений
  пункт/тип угоди/тип об'єкта лишаються незмінними. Якщо на кроці нічого
  не вводити й натиснути «➡️ Далі» - старе значення зберігається.

### 🧰 Інше

- **🚀 РОЗПОЧАТИ** - альтернатива `/start`
- **📝 Головне меню** - вихід з будь-якого кроку в будь-який момент
  (якщо `MEDIA_STORAGE=googledrive` - незбережені завантажені фото/відео

- Контроль доступу через `ADMINS` - за потреби обмежує "Додати
  об'єкт"/"Редагувати" певними Telegram ID (пошук завжди відкритий для всіх)
- Логування всіх дій і помилок (`logging` + `try/except` навколо звернень
  до Google API з повідомленням користувачу при збої)
- Повтори (`tenacity`) при тимчасових помилках Google Sheets/Drive API

## 🧮 Структура Google Таблиці

Кожен **аркуш = населений пункт**. Назва й порядок колонок (мають
збігатися з назвами нижче, порядок самих колонок у таблиці не критичний,
бо бот шукає їх за назвою заголовка):

```
Тип угоди | Тип об'єкта | Адреса / локація | Ціна | Валюта |
Площа, м² | Площа ділянки, сот. | Фото | Відео | Посилання |
Відео TikTok | Опис | Коментар | Статус
```

Приклад рядка (`MEDIA_STORAGE=googledrive`; при `=telegram` колонки "Фото"
й "Відео" замість лінків містили б Telegram `file_id` - непридатні для
прямого перегляду з самої таблиці, лише через бота):

```
Продаж | Будинок | https://maps.app.goo.gl/zBtVwvDjrNkCpnjR7 | 115000 | USD |
115 |  | https://drive.google.com/... | | https://www.olx.ua/... |
https://www.tiktok.com/@user/video/123... |
Нове будинок 115 кв.м з чистовим оздобленням | | Активний
```

Колонки **"Коментар"** і **"Статус"** бот не заповнює й не змінює під час
редагування (окрім встановлення «Активний» для щойно доданого об'єкта) -
це поля для ручних нотаток адміністратора прямо в таблиці.

**Новий населений пункт** (новий аркуш) наразі додається вручну: скопіюйте
існуючий аркуш і збережіть той самий заголовок - бот працює лише з уже
наявними аркушами (див. "Відомі обмеження" нижче).

## ⚠️ Відомі обмеження та припущення

Специфікація (`Google API.txt`) не описувала кілька деталей - нижче те,
як це реалізовано зараз, і де варто звернути увагу:

- **`GOOGLE_SPREADSHEET_ID` має вести на "рідну" Google Таблицю**, а не на
  завантажений `.xlsx`-файл - навіть якщо такий файл відкривається в
  браузері за тим самим посиланням `docs.google.com/spreadsheets/d/...`,
  Sheets API не вміє з ним працювати (помилка `This operation is not
  supported for this document. The document must not be an Office file`).
  Якщо у вас саме такий файл - відкрийте його в Google Drive і виконайте
  **Файл → Зберегти як Google Таблиці**, після чого впишіть ID НОВОГО
  файлу в `.env`.
- **Аркуші, що не є населеними пунктами** (довідники для спадних списків,
  зведені каталоги тощо) потрібно додати в `EXCLUDED_SHEETS` у `.env` -
  інакше вони з'являться в боті як "населені пункти" для вибору, хоча
  мають іншу структуру колонок.
- **Новий населений пункт** можна обрати лише зі списку вже існуючих
  аркушів - бот не створює нові аркуші сам (щоб не плодити аркуші з
  друкарськими помилками). Додайте аркуш вручну (скопіювавши наявний,
  щоб зберегти заголовок) - і він одразу з'явиться у списку бота.
- **Ідентифікація рядка для редагування** - за номером рядка на момент
  пошуку (без окремої колонки ID). Якщо рядки в аркуші сильно
  перевпорядкувати вручну між пошуком і натисканням «Редагувати», можлива
  розсинхронізація. Для типового використання (без паралельного ручного
  редагування тієї ж таблиці) це не проблема; за потреби можна додати
  окрему технічну колонку з ID.
- **Фото/відео у пошуку** показуються напряму в чаті (справжні зображення/
  відео, не лише кнопки-посилання) - кнопка-посилання лишається тільки як
  фолбек для Google Drive-файлів, які не вдалось завантажити/показати.
  Усі файли, завантажені на Google Drive, отримують доступ "за посиланням"
  (anyone with the link), щоб кнопки працювали для будь-кого.
- **`MEDIA_STORAGE=telegram`** (за замовчуванням) не має лімітів за обсягом
  даних, але Telegram офіційно (Bot Developer ToS) **не гарантує** довічне
  зберігання медіафайлів бота - на практиці видалення без причини
  трапляється вкрай рідко, але для каталогу, що ведеться роками, це
  вартий уваги ризик. `MEDIA_STORAGE=googledrive` цього ризику не має
  (платний надійний сервіс), але вимагає OAuth-токен і витрачає квоту Drive.
- **Ліміт Telegram на вхідні файли** - стандартне Telegram Bot API не
  дозволяє боту завантажити файл більший за ~20 МБ (обмеження Telegram, не
  бота) - стосується лише `MEDIA_STORAGE=googledrive` (там потрібно
  завантажити байти з Telegram перед переливанням на Drive); для
  `MEDIA_STORAGE=telegram` цього обмеження немає - file_id береться без
  завантаження файлу ботом.
- **Пошук показує всі об'єкти з непорожнім "Тип угоди"**, незалежно від
  "Статусу" (тобто проданий/архівний об'єкт теж буде показано, якщо
  "Тип угоди" не очищено вручну) - рівно як описано у специфікації.
- **Токен бота в `Google API.txt`**: цей файл тепер додано до
  `.gitignore`, але токен уже один раз "засвітився" у відкритому вигляді.
  Рекомендую перевипустити токен через [@BotFather](https://t.me/BotFather)
  (`/revoke`) і оновити його в `bot/.env`.
